# День 33: ассистент поддержки пользователей

Демо объединяет существующие named agents, RAG и новый read-only MCP-сервер `support-mcp`. RAG отвечает за общую документацию продукта, MCP — за персональные данные клиента и тикета, история named agent — за контекст разговора.

## Запуск

Требуется настроенный OpenAI-compatible chat API и embedding API (см. корневой README).

```bash
test -e mcp.json || cp mcp.example.json mcp.json
export RAG_CORPUS=support/knowledge
export LLM_EMBEDDING_MODEL=text-embedding-bge-m3

cargo run -p support-mcp
```

В другом терминале:

```bash
cargo run -p llm-cli -- rag index parent

PROMPT="$(cat support/agent-prompt.md)"
cargo run -p llm-cli -- agent add Поддержка --system "$PROMPT" --context-strategy summary
cargo run -p llm-cli -- agent rag Поддержка on parent k=4 n=12 min=0.45 rerank=heuristic
cargo run -p llm-cli -- agent start Поддержка
```

Если `mcp.json` уже существует, добавьте в него секцию `support` из
`mcp.example.json`, не перезаписывая остальные локальные настройки.

Вместо CLI можно запустить `cargo run -p llm-web`, открыть `http://127.0.0.1:8080`, выбрать агента «Поддержка» и показать вызовы MCP и RAG-источники в интерфейсе.

## Демо-запросы

Основной сценарий:

> Тикет TCK-1001. Почему не работает авторизация и что мне делать?

Ожидается вызов `support · get_ticket`. В ответе должны соединиться факты из тикета (`AUTH-LOCKED`, семь попыток, 2FA) и инструкция из `authentication.md` (15 минут, только последний код, порядок восстановления).

Продолжение проверяет контекст диалога:

> А если после 15 минут код всё равно не придёт?

Дополнительный сценарий:

> Тикет TCK-1002. Почему пропал экспорт отчётов?

Ответ должен учитывать тариф Free и `payment_hold`, а не давать общую инструкцию без данных клиента.

Негативная проверка:

> Посмотри тикет TCK-9999.

Ассистент должен сообщить, что тикет не найден, а не придумывать его содержание.

## Проверка кода

```bash
cargo fmt --all -- --check
cargo test -p support-mcp
```

Тесты проверяют загрузку демо-CRM, связи тикетов с пользователями, сортировку
истории по времени и отказ при дублирующихся или неизвестных идентификаторах.

## План видео

1. Показать четыре файла базы знаний и JSON CRM.
2. Запустить `support-mcp`, затем открыть вкладку MCP и вызвать `get_ticket` вручную.
3. Показать, что база знаний проиндексирована и у агента включён RAG.
4. Отправить основной запрос и раскрыть строку вызова MCP и источники RAG.
5. Задать короткий вопрос-продолжение без повторения тикета — это демонстрирует контекст агента.
