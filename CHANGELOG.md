# Changelog

Все заметные изменения проекта — по дням челленджа, от новых к старым.
Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [Unreleased] — День 35 (в работе)

### Добавлено

- **Ассистент записей `media-assistant`** — доводит запись встречи от видео до саммари: WebM/MP4 → `output.mp4` → `output.mp3` → MP3-чанки → транскрипт → саммари. Заменяет скилл `convert-summarize` для Claude Code и Codex.
- **MCP-сервер `media`** (`mcp/media-mcp`) — `inspect` находит последний годный чекпоинт и называет следующий шаг, шаги вне очереди отказывают; сверка длительности `output.mp4` с WebM; негодные артефакты — в `diagnostics/`.
- **Задания** — конвертация, извлечение, нарезка, транскрипция и саммари идут в фоне сервера, одно на каталог; успех — только код выхода 0. Ожидание делает код ассистента, ход виден в TUI.
- **Транскрипция** — всегда все чанки, не больше двух запросов разом, повторы; транскрипт — только из полного набора этого запуска.
- **Саммари** — LM Studio по шаблону книжного клуба, ответ в Markdown; модель выбирается сама, если пригодная или загруженная одна, иначе вопрос пользователю.
- **Саммари для Telegram** — инструмент `telegram_summary` (Python-библиотека `telegramify-markdown`, `media/requirements.txt`): `output-summary-telegram.md` — вставить в приложение Telegram (`**жирный**`, `__курсив__`), `output-summary-telegram-bot.md` — MarkdownV2 для бота; сам ничего не отправляет; шаг пайплайна после саммари, устаревшая версия пересоздаётся. `pyromark` закреплён на 0.9.14: с 0.10 библиотека теряет текст с `~` или `$`.
- Интерфейсы: TUI (`cargo run -p media-assistant`), CLI (`media-assistant run … --summary yes|no`), сервер по HTTP (`--http`, порт 8098) для других клиентов MCP. Диалоги — в `media/runs/<id>/`.

## [День 34] — 2026-10-16

### Добавлено

- **Ассистент файлов `file-assistant`** — ассистент, который сам работает с файлами проекта: ему ставят цель словами, а какие файлы искать, читать и править, он решает сам.
- **MCP-сервер `fs`** (`mcp/fs-mcp`) — список файлов, поиск по содержимому, чтение, создание и правка файлов; песочница путей, оверлей ожидающих изменений, дифф.
- **Правки не пишутся на диск сами** — копятся как ожидающие, показываются диффом, записывает их пользователь (`/apply`, `--apply`).
- **Сценарии** (`files/scenarios/*.md`) — готовые цели: `usages`, `docs-sync`, `changelog`, `invariants`.
- **Сохранение запусков** (`files/runs/<id>/`) — отчёт, патч, журнал вызовов, метаданные.
- Интерфейсы: TUI (`cargo run -p file-assistant`) и CLI (`file-assistant run …`).

## [День 33] — 2026-10-15

### Добавлено

- **Ассистент поддержки `support-assistant`** — отдельный мини-сервис поддержки продукта CloudDesk (демо): консультант по продукту и разбор конкретного тикета с учётом данных клиента из CRM.
- **RAG по базе знаний** — документация и FAQ продукта из `support/knowledge/*.md` в собственном индексе `rag/support.db`; база сверяется с файлами по SHA-256 перед каждым ответом.
- **MCP-сервер `support-mcp`** — CRM только для чтения: пользователи и тикеты из `support/data/*.json`.
- **Контекст сессии** — сервис помнит тикет и последние обмены, уточняющий вопрос без номера тикета понимается в контексте.
- Тикет запрашивает код, а не модель: ответ с учётом тикета не зависит от того, догадается ли модель вызвать инструмент.
